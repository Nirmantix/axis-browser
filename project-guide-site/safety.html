Browser automation has sharp edges.

Keep secrets out of artifacts, treat protected sites as permission-gated, and choose shared or isolated browsers deliberately.

Hard rules

Artifacts stay under .tmp/

Screenshots, traces, scrapes, reports, verified runs, cookies, and generated credentials must not be committed.

Secrets stay user-local

Do not write API keys into repo files, .env, .tmp/, generated scripts, MCP snippets, or screenshots.

Protected sites need permission

Use BrowserAct, Notte, CloakBrowser, or Firecrawl on protected targets only when explicitly authorized.

What the runtime enforces for you

These boundaries are enforced in code, not by convention. They matter because CDP itself has no authentication — anything that reaches the browser's endpoint gets full control of it.

Capability token on the bridge

The bridge's port is deterministic, so "reachable from localhost" used to mean "able to drive your browser". Each bridge now generates 32 random bytes when it binds, stores them in its session record (0600, inside a 0700 state directory that is verified private before the secret is written), and answers 401 to every request that does not present them in x-axis-bridge-token. The CLI reads and sends it for you; it is never printed, and a refusal is logged without header values, URLs, query strings or tokens.

Anti-rebinding gate on the bridge

The bridge serves /health, /tools, and /call on loopback, and /call maps straight to a tool invocation. A gate now runs first on every route and rejects any request whose Host or Origin is not loopback, returning 403 {"error":"Forbidden host"}. Without it, any page you visited could rebind its own domain to 127.0.0.1 and drive CDP from your browser (GHSA-x439-jhfh-v9x2).

Bounded /call payloads on the bridge

After the host/origin gate and the token check, POST /call enforces a 1 MiB request-body cap (1048576 bytes): an oversized declared Content-Length is refused up front with 413, and a chunked or understated body is cut off mid-stream without invoking any tool. The cap is per call, not per axis-browser run script — run streams stdin whole, so split oversized inline data into files or chunked reads.

Keychain isolation for browsers Axis launches

ephemeral and managed always pass --use-mock-keychain and --password-store=basic, so a browser this tool starts cannot reach your OS password store. attach and autoconnect deliberately omit them — that browser's keychain policy belongs to whoever started it.

Nothing is killed on the strength of a stale pid

stop, bridge recycling and reap re-read the live process identity — command line and start time — immediately before every SIGTERM and SIGKILL, so a pid the operating system recycled in between is skipped and reported instead of killed. A process group is only signalled when the target still leads it, and there is no group kill after the leader exits. A record left by an older release carries no token: no command adopts one, and only an explicit axis-browser stop retires it, after verifying the process twice.

Never export a connection variable globally

A CHROME_DEVTOOLS_AXI_BROWSER_URL exported from a shell profile reaches every shell and child process that sources it — including the non-interactive ones coding agents run in, where nobody sees it. Scope connection settings to a single command or a project, and prefer CHROME_DEVTOOLS_AXI_MODE=managed as a default. Run axis-browser doctor to see what your environment is actually set to.

Shared versus isolated browser mode

Mode Use when Risks
ephemeral (Axis owns it, no profile) Reproducible or destructive checks, parallel agents, CI. The default. Starts logged out every time. Keychain-isolated.
managed (Axis owns it, persistent profile) A login must survive between runs. Sign in once with axis-browser login <url>. Holds real cookies on disk under the session profile. Keychain-isolated. A newly created named session starts logged out; later runs reuse that profile and keep the login.
A browser Axis does not own (attach / autoconnect) Real login, SSO, cookies, manual continuity, or cross-tool state matters. Can see real account data. Not keychain-isolated — that browser's policy is whoever started it. Do not close user tabs from Playwright; use disconnect().
Isolated Playwright Clean reproducibility, CI, destructive tests, or parallel agents matter. May not include real login state. Use test accounts and explicit test data.
Cloud/service browser Replay, live viewer, managed identity, or production browser workflows matter. Paid/API-backed. Credential setup must stay user-local and provider-specific.

Evidence rules

STEP_PASS

Use only when the check actually passed. Optional evidence paths are validated when present.

STEP_FAIL

Use when expected behavior did not happen. Include a screenshot path when useful.

STEP_SKIP

Use when a prerequisite is missing. Skipped work is honest, but it is not a pass.

No-go list

Do not invent credentials

If login blocks the task, ask the operator to log in or provide a test account through an approved local channel.

Do not hide failed checks

Report STEP_FAIL or STEP_SKIP. Do not remove plan checks to force a green validator.

Do not use stealth tools casually

CloakBrowser and protected-site flows are narrow, authorized-use paths, not defaults.

Do not nest LLM loops

Webwright is not part of the runtime stack. Host agents drive Axis Browser and browser-bay directly.
